# AndroidPhotos33

An Android port of the Photos33 JavaFX application, built for CS213 Software Methodology at Rutgers University.

---

## Our Use of AI

### Backend (Model Layer)
The backend was **not generated by AI**. The `Album`, `Photo`, and `Tag` model classes were carried over directly from our original Photos33 JavaFX project and lightly adapted for Android (e.g., adding a URI-based constructor to `Photo` to handle Android content URIs instead of file paths).

### UI / XML Layouts
We drew out our UI structure on paper first — sketching the screen layouts, what buttons go where, and how the navigation should flow between screens. We then uploaded those drawings and descriptions to AI (Claude) and had it generate the corresponding XML layout files. Screens designed this way include:

- `activity_main.xml` — Album list home screen
- `activity_album.xml` — Photo grid inside an album
- `activity_photo.xml` — Single photo display with slideshow and tag management
- `activity_search.xml` — Search screen with AND/OR tag filtering and autocomplete

### Adapters
The adapters (`AlbumAdapter`, `PhotoAdapter`) were a mix of AI and manual work:

- The overall **structure** of the adapters (RecyclerView, ViewHolder pattern, interface definitions) was generated with AI assistance.
- The **selection highlighting logic** — tracking `selectedPosition`, updating the `MaterialCardView` stroke and background color on long-press, and the `clearSelection()` method — was written manually, since understanding how to wire the visual state to the adapter position required working through it ourselves.
- The `OnPhotoClickListener` / `OnPhotoLongClickListener` interface split was also done manually after running into a compile error where a two-method interface cannot be used as a lambda.

### Activity Logic (Java)
The activity classes (`MainActivity`, `AlbumActivity`, `PhotoActivity`, `SearchActivity`) were **written by us**, using AI for reference when needed. This includes all business logic for album CRUD operations, photo add/remove/move, tag management, serialization/deserialization, and the search AND/OR prefix-matching algorithm.

---

## Screens and Features

| Screen | Features |
|---|---|
| Home (`MainActivity`) | Lists all albums, create / rename / delete albums, navigate to search |
| Album (`AlbumActivity`) | Photo grid, add photo from device, remove photo, move photo to another album |
| Photo (`PhotoActivity`) | Full photo display, prev/next slideshow, add tag (person/location), delete tag |
| Search (`SearchActivity`) | Search by tag type + value, AND/OR conjunction, prefix autocomplete, results grid |

## Notes
- No Kotlin was used. The entire project is Java only.
- No external image loading libraries (e.g. Picasso, Glide) were used per assignment requirements.
- Data is persisted across sessions using Java serialization (`albums.ser`).
